# Zouroboros swarm executors

An *executor* is a local agent the orchestrator can hand a prompt to. Each one has an entry in
the profile's registry (`$HERMES_ZOUROBOROS_HOME/executors.json`, generated by
`bun integration/cli.ts init`) and, for local CLIs, a **bridge script**. The bridge takes
`"<prompt>" [workdir]`, prints only the final answer on stdout, and exits non-zero on failure.

The distribution generates one executor, `hermes-vps`. It is a one-shot `hermes -z` run through
`integration/hermes-bridge.sh`, with a timeout (`HERMES_TIMEOUT`, seconds) and optional
`HERMES_BIN`, `HERMES_MODEL` and `HERMES_PROVIDER` overrides.

## Commands

```bash
bun "${HERMES_SKILL_DIR}/scripts/executors.ts" list     # id, transport and bridge of each executor
bun "${HERMES_SKILL_DIR}/scripts/executors.ts" doctor   # bridge present + health command matches; exit 1 if any fails
```

`doctor` runs each entry's `healthCheck.command` (for Hermes: `hermes --version`, honouring
`HERMES_BIN`). It reports pass/fail only, never the command output.

## Troubleshooting a failed swarm or autoloop task

1. Run `executors.ts doctor`. If `health` fails, Hermes is not on `PATH`. Install it or set `HERMES_BIN`.
2. `Hermes failed (exit N)` from the bridge means the provider call failed. The bridge suppresses
   provider stderr on purpose because it can contain credentials. Inspect the Hermes session logs
   of the profile in `$HERMES_ZOUROBOROS_HOME/hermes`.
3. `Hermes produced no final response` means the model returned nothing. Retry with a clearer task
   or a different model (`HERMES_MODEL`).
4. Timeouts: raise the task's `timeoutSeconds` (maximum 600) or split the task.

## Adding a bridge for another agent CLI

1. Copy `${HERMES_SKILL_DIR}/templates/template-bridge.sh` outside the skill tree and implement it
   according to `${HERMES_SKILL_DIR}/references/bridge-protocol.md`.
2. Do not echo provider stderr to stdout or logs. Enforce a timeout. Never start another swarm
   from inside a bridge.
3. Add an entry to the profile's `executors.json` with an absolute `bridge` path and a
   `healthCheck`, then run `doctor`.

The distribution's swarm CLI and task contract always dispatch to `hermes-vps`. Extra registry
entries are for your own tooling (for example `autoloop.ts --executor <id>`) and are not
selected automatically.
